# Анкета ОТиПБ — техническое описание

Документ описывает, как устроена система: из чего состоит, что за что отвечает,
где оказываются данные, что сделано для безопасности и что остаётся слабым.

---

## 1. Состав системы

| Часть | Технологии | Где лежит | Что делает |
|---|---|---|---|
| Анкета (фронтенд) | React 19, Vite 8, Tailwind 4 | `app/` | Три экрана в одном приложении: анкета работника, анкета визитёра, генератор ссылок |
| Бэкенд | Node.js 20, Express 5 | `backend/` | Выдаёт ссылки, принимает анкеты, собирает Excel, отправляет письма |
| Веб-сервер | nginx | конфиг на сервере | HTTPS, раздача статики, проксирование `/api/` на порт 3002 |
| Процесс-менеджер | pm2 | `newcomer-backend` | Автозапуск бэкенда, логи |

Базы данных нет. Единственный файл состояния — `sessions.json` (см. блок 7).

## 3. Поток: анкета работника

```
Генератор ссылок  →  ссылка с ?id  →  работник заполняет  →  письмо получателям
```

1. **Выдача ссылки.** `POST /api/admin/create-link` с паролем. Сервер создаёт
   `linkId` — 8 случайных байт (16 hex-символов) — и записывает в `sessions.json`
   адреса получателей. Возвращает `linkId`.
2. **Открытие анкеты.** Браузер грузит приложение, `GET /api/session/:linkId`
   подтверждает, что ссылка существует. Если ссылки нет — анкета всё равно
   открывается и заполняется вручную; данные человека дороже строгости.
3. **Заполнение.** Проверки идут на стороне браузера: массив `checks` считает
   готовность каждого поля, из него же берётся полоса заполнения. В состоянии
   ошибок хранится **название сообщения**, а не готовый текст — поэтому подписи
   переводятся при переключении языка.
4. **Отправка.** `POST /api/submit`, `multipart/form-data`: поле `data` — JSON
   анкеты, остальные поля — сканы и фотографии.
5. **Обработка.** `normalizePayload` приводит анкету к одному виду (есть
   совместимость со старым форматом), `buildSummaryRow` раскладывает её
   в 52 колонки, `exceljs` собирает файл в памяти.
6. **Письмо.** Уходит получателям из записи ссылки. Вложения: Excel и все сканы.
7. **Уборка.** Загруженные файлы удаляются с диска сразу — на всех путях,
   включая ошибку отправки.

## 4. Поток: заявка визитёра

Отличия от анкеты работника:

- Адрес `/visitor`, своя ссылка (`kind: 'visitor'`), свой эндпоинт
  `POST /api/visitor/submit`.
- Поля: ФИО, должность, дата рождения, направления посещения (можно несколько),
  характер работ (самостоятельно / только в сопровождении), телефон и почта —
  необязательно.
- **Та же таблица из 52 колонок.** Заполняются 7: статус `Visitor`, ФИО,
  латиница, должность, дата рождения, почта, телефон. Колонки обучений остаются
  пустыми: у визитёра про них не спрашивали, и «не требуется» было бы выдумкой.
- Направления, характер работ и признак Полярного Экспресса в колонки не
  попадают — им место в теле письма.
- Ссылка осмысленна и без `?id`, поэтому на неё можно напечатать QR-код.

### Перекрёстные ссылки

Ссылка одного типа не годится для анкеты другого:

| Запрос | Результат |
|---|---|
| `GET /api/session/<ссылка визитёра>` | 404 |
| `GET /api/visitor/session/<ссылка работника>` | 404 |
| `POST /api/submit` со ссылкой визитёра | анкета доставляется, но **по адресам охраны труда**, расхождение пишется в лог |
| `POST /api/visitor/submit` без ФИО и даты рождения | 400, письма нет |

## 5. Генератор ссылок (админ-панель)

Открывается по `#/admin`. Умеет:

- выбрать тип ссылки — анкета работника или анкета визитёра;
- задать получателей заполненных анкет;
- для работников — скачать готовый файл письма `.eml` (открывается в Outlook
  с подставленными адресами и текстом на двух языках);
- для визитёров — показать и скачать **QR-код**. Код рисуется локально
  в браузере вектором (SVG); библиотека `qrcode` подгружается отдельным файлом,
  чтобы не утяжелять анкету. Кнопка отдаёт PNG 1024 px, при отказе canvas —
  тот же код вектором.

## 6. Сводная таблица (52 колонки)

Состав колонок и правила заполнения — в `backend/table.js`, человеческое
описание с примерами — в `app/СПРАВОЧНИК_ЛИТЕР.md`.

Ключевые правила:

- Колонка ФИО остаётся кириллической, даже если анкету заполняли по-английски.
- Латиница берётся из паспортных полей, а при их отсутствии — транслитерацией.
- Место под 5 протоколов промбезопасности и 5 прочих обучений; пустые колонки
  сохраняются, чтобы строка не «съезжала» при вставке.
- Срок действия аттестации — 5 лет; «сегодня» считается в поясе объектов
  (`Asia/Anadyr`, UTC+12), а не в поясе сервера. Разница в 10 часов иначе
  сдвигала остаток срока на сутки.

## 7. Что и где хранится

| Данные | Где | Сколько живут |
|---|---|---|
| Заполненная анкета | только в письме получателям | на сервере не остаётся |
| Сканы и фотографии | `uploads/` на время обработки | удаляются сразу после отправки письма |
| Файл Excel | собирается в памяти | на диск не пишется |
| Выданные ссылки | `sessions.json`: идентификатор, тип, адреса получателей, дата создания | до ручного удаления |
| Логи | pm2, `/root/.pm2/logs/` | до ручной очистки |

`sessions.json` пишется атомарно: сначала временный файл, потом переименование.
Иначе прерванная запись делала недействительными **все** выданные ссылки сразу.

## 8. Персональные данные

Правило: **персональные данные не остаются на сервере.** Что из этого следует:

| Место | Что можно | Что нельзя |
|---|---|---|
| Тело письма | фамилия с инициалами, должность, потребность в обучении | дата рождения, телефон, почта, гражданство, СНИЛС, ИНН, паспорт |
| Строка для вставки и файл Excel | все 52 колонки — это и есть цель письма | — |
| Логи сервера | получатели, количество и вес вложений | ФИО и любые данные работника |
| Адреса ссылок | идентификатор ссылки | любые персональные данные |
| Снимки для откатa (`deploy.sh`) | код и конфиги | `sessions.json`, `.env` |

Почему в адресах нельзя: такой адрес остаётся в истории браузера, в пересланном
письме и в закладках. Из-за этого удалены кнопка «скопировать информацию для
реестра» и страница, на которую она вела; адрес `/copy` отдаёт `410`.

В анкете работник подтверждает согласие на обработку данных (152-ФЗ) и на
передачу их в учебный центр — без галочки отправка не проходит.

## 9. Безопасность

### Что сделано

- **HTTPS** на всех адресах, сертификат Let's Encrypt, автоматическое продление.
- **Ссылки непредсказуемы:** 8 случайных байт из `crypto.randomBytes`,
  перебор бессмыслен.
- **Ограничение веса вложений** — 18 МБ на письмо (`MAX_ATTACHMENTS_BYTES`),
  плюс 50 МБ на запрос в nginx. Иначе одна анкета с фотографиями могла
  положить отправку.
- **Очередь отправки:** письма уходят по одному, одно соединение к SMTP.
  Параллельные отправки роняли соединение.
- **Временные файлы удаляются** на всех путях, включая ошибки.
- **Валидация тела запроса:** пустое тело даёт 400, а не «успешно» с пустым
  письмом.
- **Проверка типа ссылки** на всех трёх эндпоинтах, где это имеет смысл.
- **Кэширование:** `index.html` — `no-store`, файлы сборки — `immutable`
  с хэшем в имени. Иначе после выкатки люди неделями видят старую версию.

### Что остаётся слабым

| Проблема | Чем грозит | Что сделать |
|---|---|---|
| **Пароль генератора ссылок — 3 символа** | перебирается мгновенно | длинный пароль в `.env` |
| **Нет ограничения попыток ввода пароля** | перебор ничем не сдерживается | лимит попыток по IP |
| **Вход в генератор на стороне браузера декоративный** | экран открывается с любым непустым паролем; настоящая проверка — на сервере при создании ссылки, то есть создать ссылку без пароля нельзя, но интерфейс вводит в заблуждение | проверять пароль на сервере при входе |
| **CORS открыт для всех источников** (`cors()`) | чужой сайт может обращаться к API от имени посетителя | ограничить своим доменом |
| **Отправка идёт через личный ящик на Яндексе** | письма приходят с внешнего адреса, зависят от чужого сервиса | корпоративный ящик и SMTP-релей |
| **Адреса получателей по умолчанию зашиты в код** | меняются только правкой кода | вынести в `.env` |
| **Список работников в генераторе ссылок** | если им пользоваться, ФИО и почта снова окажутся в `sessions.json` | убрать поле или принять осознанно |

## 10. Адреса

| Адрес | Что отдаёт |
|---|---|
| `/` | анкета работника (`?id=…` — конкретная ссылка) |
| `/visitor` | анкета визитёра. Регистр не важен, лишний хвост пути не мешает |
| `#/admin` | генератор ссылок |
| `/tools/` | панель инструментов отдела (вне этого репозитория) |
| `/preview/` | тестовый контур: та же анкета, собранная отдельно |
| `/copy` | `410` — страница удалена вместе с кнопкой в письме |
| `/api/*` | бэкенд на порту 3002 |

Тип анкеты определяется **путём**, а не фрагментом и не параметром: фрагмент
`#/visitor` срезают сокращатели ссылок и превью в мессенджерах, и человек молча
получил бы не ту анкету. Все адреса строятся от `import.meta.env.BASE_URL`,
иначе ссылки из тестового контура уводили бы на боевой.

## 11. Почта

| Параметр | Значение |
|---|---|
| Транспорт | SMTP, `nodemailer` |
| Отправитель | адрес из `.env` (`SMTP_USER`), с человеческим именем в поле «От кого» |
| Ответить | личная почта работника — чтобы можно было ответить ему напрямую |
| Получатели | из записи ссылки, иначе адреса по умолчанию |
| Вложения | Excel + загруженные сканы |

Имя отправителя и обратный адрес заметно влияют на доставляемость: без них
корпоративная почта охотнее отправляет письмо в спам. Задержка доставки
до нескольких минут — норма для корпоративных фильтров, это не потеря письма.

## 12. Сборка и выкатка

```bash
cd app && npm install        # зависимости
npm run dev                  # разработка
npm run build                # боевая сборка → dist/
npm run build:preview        # тестовая сборка → dist-preview/ (база /preview/)
npx eslint src --ext .js,.jsx
```

Выкатка на сервере:

```bash
/root/backups/deploy.sh preview   # только тестовый адрес
/root/backups/deploy.sh prod      # снимок → сборка → статика → перезапуск pm2
/root/backups/rollback.sh         # откат на снимок
```

Снимок перед выкаткой делается автоматически и **не включает** `sessions.json`
и `.env`.

Переменные окружения (`backend/.env`, в репозиторий не попадает):

```
SMTP_USER=      # ящик, с которого уходят письма
SMTP_PASS=      # его пароль
ADMIN_PASS=     # пароль генератора ссылок
VISITOR_RECIPIENTS=   # необязательно: получатели заявок визитёров
```

## 13. Тесты

Проверки гоняются в `jsdom` — то есть анкета действительно рисуется, заполняется
и отправляется, а перехваченные данные прогоняются через настоящий код бэкенда.
Это ловит расхождения между тем, что шлёт форма, и тем, что ждёт сервер.

| Набор | Что проверяет | Проверок |
|---|---|---|
| Сквозной | заполнение анкеты целиком → payload → 52 колонки → Excel → тело письма | 77 |
| Отрисовка | что видно на экране, обязательные поля, переводы | 49 |
| Анкета визитёра | маршрут, поля, отправка, попадание в таблицу | 54 |
| Придирчивый разбор визитёра | краевые случаи: битая ссылка, короткое ФИО, подписи ошибок | 36 |
| Генератор ссылок и QR | тип ссылки, адрес, содержимое QR-кода, скачивание | 18 |
| Переводы ошибок | подписи переводятся вместе с интерфейсом | 8 |
| Таблица | правила заполнения 52 колонок, строка для копирования | 43 |

## 14. Что требует решения

1. **Пароль генератора ссылок** — 3 символа, без ограничения попыток.
2. **Перенос на корпоративный ресурс** — сервер внешний; переписка с ИТ идёт.
3. **Корпоративный ящик вместо личного** — адрес сервера SMTP сейчас зашит
   в код, при переносе его тоже надо вынести в настройки.
4. **Список работников в генераторе ссылок** — убрать или оставить осознанно.
5. **Реестр обучений** — отдельное приложение, хранит персональные данные
   194 работников; к этому репозиторию не относится, но вопрос тот же.
